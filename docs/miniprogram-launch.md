# 微信小程序上线指南（Mini-V1）

本目录下 `miniprogram/` 是基于主分支「今天吃啥？」APP 原生重写的微信小程序，`cloudfunctions/` 是账号登录用的云函数。

- AppID：`wx603e02387ba0a6e0`
- 平台：微信小程序（原生 WXML/WXSS/JS，未用跨端框架）
- 登录：微信一键登录（微信云开发，`cloud.getWXContext().OPENID` 识别用户）
- 数据：本地优先（`wx` storage），**不预置、不打包食谱**，用户通过「导入中心 / 数据→导入」自行导入

## 一、准备

1. 安装[微信开发者工具](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html)（稳定版）。
2. 用小程序管理员微信扫码登录（该微信需是小程序的管理员/开发者）。

## 二、导入项目

1. 打开开发者工具 → 「导入项目」→ 目录选择本仓库根目录（含 `project.config.json`）。
2. AppID 会自动带出 `wx603e02387ba0a6e0`；若提示填写，手动填入。
3. 点击「确定」，工具会用基础库编译 `miniprogram/`。

## 三、开通云开发并部署登录云函数

1. 在开发者工具顶部点「云开发」，首次需开通并创建一个环境（免费额度够个人用）。
2. 记下环境 ID。若只有一个环境可跳过；若有多个，把 `miniprogram/utils/config.js` 里的 `CLOUD_ENV` 填成对应环境 ID。
3. 在「云开发 → 数据库」新建集合 `users`（权限默认「仅创建者可读写」即可，云函数用服务端 SDK 不受影响）。
4. 回到编辑器，在 `cloudfunctions/login` 和 `cloudfunctions/saveProfile` 目录上分别右键 → 「上传并部署：云端安装依赖」。

> 说明：`login` 云函数通过 `cloud.getWXContext().OPENID` 直接拿到用户 openid，无需你在代码里处理 AppSecret；首次登录在 `users` 集合登记，之后更新 `lastLoginAt`。

## 四、本地运行验证

1. 工具栏「编译」跑起来后：
   - 默认进入「菜单计划」，可切前一天/后一天、搜索加菜、勾选食材加入采购清单。
   - 「我的」页点「微信一键登录」，成功后显示昵称/头像（头像用 `open-type="chooseAvatar"`、昵称用 `type="nickname"` 填写）。
   - 若未开通云开发，应用自动降级为「本地模式」，仅登录功能不可用，其余功能正常。
2. 真机预览：点「预览」扫码，在手机微信里实测登录与数据导入。

## 五、小程序图标（头像）

小程序图标在**微信公众平台**（mp.weixin.qq.com）「设置 → 基本设置 → 小程序头像」上传，不是在开发者工具里传：

- 用 `assets/brand/app-icon-144.png`（144×144）或 `assets/brand/app-icon-1024.png`（高清，平台会自动缩放）。
- 图标即 APP 导航栏的黄色简笔画：黄色圆角底 `#f8d46b` + 深绿 `#254139` 的汤碗简笔画（源文件 `assets/brand/app-icon.svg`）。

## 六、提交审核与发布

1. 开发者工具点「上传」，填版本号（如 `1.0.0`）与备注。
2. 登录微信公众平台 → 版本管理，把刚上传的版本「提交审核」。
3. 审核通过后点「发布」即上线。

## 七、当前实现边界与后续

- 已实现：菜单计划（日视图/加菜/弹窗勾选/改日期/删除/上移下移排序）、食谱库（信息流/搜索/分类/展开做法/加到菜单/编辑/删除）、食谱编辑（成品图上传/食材排序）、采购清单（勾选排序/手动添加/批量删除/复制）、导入中心（粘贴文本解析）、我的（登录/数据导出导入/备份/反馈/统计）。
- 数据层：`miniprogram/utils/` 复刻主分支领域逻辑（食谱/菜单/采购/搜索/迁移）；`utils/storage.js` 保留 `meal-planner-app-v1` 数据键与迁移逻辑。
- 图片落盘：小程序单个 storage key 上限约 1MB，成品图 base64 会超限，因此保存时把成品图写成本地文件（`utils/images.js`），storage 只存路径，导出时再读回 base64。
- 尚未做（后续轮次）：拖动排序（现为菜单内上移/下移）、OCR 文字识别（小程序需接微信 OCR 插件，暂未接入）、云同步（登录已就绪，数据仍本地，云数据库 `users` 仅存账号资料）。
- 部署配置（`.github/workflows/`）未改动；`recipes.json` 未打包进小程序。
