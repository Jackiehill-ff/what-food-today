# Decisions

## 本地优先和兼容迁移

- 当前应用必须继续支持未登录用户使用本地功能。
- 现有 `localStorage` 数据是重要用户数据，账号 + 云同步不能直接覆盖或丢弃。
- 新增持久化字段时，必须更新读取时的兼容迁移逻辑。
- 如果重命名数据字段，必须检查旧字段引用，尤其是 `name`、`steps`、`notes`、`seasonings`。

## 导入中心

- 导入入口支持从 flomo 或其他文本来源粘贴食谱文本。
- 一个文本中可能包含多个食谱，需要拆分成多个草稿。
- 解析后先进入可编辑预览，不直接自动保存。
- 预览中可编辑标题、食材、做法。
- 食材只填名称也可以保存。
- 解析失败或解析不完整时必须保留 `rawText`，不要丢原文。

## 食谱卡片与首页展示（2026-09-01）

- 首页"今天的菜单"使用与食谱库相同的卡片样式（菜名 + 食材名称），保持视觉一致性。
- 卡片名称下方只展示食材名称（不含调味料），仅显示名称（不含数量/单位），用空格分隔；由 `getRecipeIngredientSummary` 统一生成。
- 食谱编辑模式支持食材/调味料排序：每行增加上移/下移按钮，仅调整同一分类内的顺序（不与另一分类跨界交换），移动端同样可用。

## 批量导入脚本（2026-09-01）

- flomo 导出文本通过 `scripts/build-recipes-json.mjs` 批量转换为 `recipes.json`，再由 App「数据 → 导入」导入。
- 解析策略：按 `【N】` 笔记标记切分；从标签提取食谱分类；括号感知的食材名切分；调味料自动识别（内置词表）；名称清理（去数量/单位/句号/`等`）；字段别名覆盖多种异构写法；手工覆盖无法自动解析的笔记。
- 源文本 `scripts/flomo-export-2026-09-01.txt` 保留为审计底稿，不纳入版本控制（已在 `.gitignore` 中忽略）。

## 账号 + 云同步前置原则

- 第一版账号 + 云同步方案采用 Supabase Auth + Supabase Postgres + RLS。
- 前端只能使用 publishable key；secret/service key 不能进入浏览器代码或环境变量示例。
- 未配置 Supabase 时必须自动降级为纯本地模式。
- v1 登录方式优先邮箱 Magic Link/OTP；GitHub OAuth 可作为后续第二入口。
- 账号系统不应阻断当前本地使用方式。
- 云同步上线前必须明确首次登录的数据合并策略。
- 必须明确同一用户多设备编辑时的冲突处理策略。
- 必须明确离线编辑、同步失败、重试和回滚行为。
- 不允许在没有迁移和备份思路的情况下，用远端数据覆盖本地 `meal-planner-app-v1`。

## 导航与信息流改版（2026-09-03）

- 取消首页：默认进入「菜单计划」，`Tab` 只保留 菜单计划/导入中心/食谱库/采购清单/我的。
- 导航统一为竖向可收放：桌面侧栏可折叠为图标窄栏；移动端用左上角汉堡按钮 + 左侧抽屉替换底部固定 Tab（更符合「竖向可收放」的要求）。抽屉内只放品牌 + 导航，账号/数据/统计仍归「我的」页。
- 食谱库信息流优先：默认展示所有食谱卡片（名称 + 基本食材），轻点展开完整做法与编辑/删除；编辑复用原 `RecipeForm` 作为独立编辑页，左上角返回箭头回信息流。
- 采购清单手动添加改为「按钮 + 弹窗」，与「复制清单」并列在标题行，避免常驻表单占据空间。

## 导入中心：网址抓取与图片识别（2026-09-03）

- 粘贴网址自动抓取：**纯前端不可行**。浏览器 `fetch` 跨域受 CORS 限制，绝大多数食谱站不返回 `Access-Control-Allow-Origin`；小红书/抖音/Instagram/YouTube 等还需登录与反爬、JS 渲染，静态抓取拿不到内容。若要做需引入后端代理/服务（超出当前纯前端应用范围），暂不实现。
- 上传图片识别文字：**可行**，采用 `tesseract.js` 浏览器端 OCR（中英文 `chi_sim+eng`），结果填入导入文本框后再走既有「解析」流程；worker/core/语言包运行时从 CDN 下载（首次识别需联网，约十几 MB）。
- 反馈功能：无后端，采用「提交到 GitHub Issues（预填标题正文）+ 复制文本」双通道。

## 成品图与本轮交互决策（2026-09-05，分支 app-v1）

- 成品图存 data URL 直接嵌进食谱 JSON（批量脚本 240px/q55、App 内上传 480px/q0.68），不建图床、离线可用。硬约束是 localStorage 约 2.6M 字符上限（Android WebView 实测口径），因此全库图片压在 ~1MB 量级，`recipes.json` 控制在 1.6MB 左右；未来全量 163 张嵌入需再收紧压缩参数或改用 IndexedDB 存图。
- 图片数据源优先级：**flomo 笔记原图 > 网络搜索图 > 空**。flomo 原图是用户自己做的菜、标题可精确匹配（`extract-flomo-images.mjs`），网络搜索图仅作早期过渡（实际已被全部替换，映射文件于 2026-09-05 按用户要求删除）；笔记无图的食谱按需求留空，不用网络图补。
- 网络图片搜索可行性结论：直接 curl Bing/DuckDuckGo 图片接口会返回缓存垃圾结果，不可用；image-search MCP 可用（返回中文图述可判断水印/包装/广告图），但单张质量参差、需多轮重试，性价比低于 flomo 原图。
- App 内上传图片用 canvas 压缩后再存，`saveAppState` 捕获 localStorage 配额异常（console.error），超限不再抛错打断应用。
- 采购清单排序改为「未勾选按分类+时间在前，已勾选按勾选时间垫底」：边买边勾的场景下，最新勾掉的沉底，剩余要买的始终在视野内；`checkedAt` 只在勾选动作时写入。
- 菜单计划排序用 pointer 事件实现拖拽（鼠标/触屏通用），不用 HTML5 DnD（Android WebView 触屏不触发）。
